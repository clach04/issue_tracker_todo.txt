done.txt (the Archive) lines are written by `close` as `x <completion-date> <original line>`, so a priority token sits AFTER the `x <date>` prefix, e.g. `x 2026-11-07 (C) 2026-11-06 Fix typos ... hash:968bb8bf`. Standard todo.txt order is `x <completion-date> <creation-date> (P) title`, i.e. (P) before the completion date is not required but (P) anywhere after `x` must be found by a parser that skips the `x <date>` prefix.

Three symptoms observed 2026-11-07 on the 13-line done.txt:
1. `_title_from_line` never strips the leading `x <completion-date>` prefix. It only drops leading `(P)` / date tokens, so an archived title is derived as "x 2026-11-07 (C) 2026-11-06 Fix typos in AGENTS.md". Title-substring lookup of an archived issue therefore cannot match its real title.
2. Because the priority token sits after the `x <date>` prefix, any check for a leading `(P)` token misses it. Only 4 of 13 archived lines carry a priority token at all (older lines were added without -p); for those that do, the token is not at position 0.
3. `list --closed -p <letter>` uses a substring test ("(C)" in line), which happens to work, so the bug is invisible today; it blocks the priority-filter grammar (A-C, C+, C-) on --closed, which is deferred on this issue.

Could be split into "parse bug" (_title_from_line / archived title derivation) and "`--closed` filter gap" (priority filtering for the Archive). Not done here: `list --closed` keeps today's exact-match -p; see docs/plans/list-sort-and-priority-filter.md decisions 9/15.
Settled 2026-11-07 (grill follow-up): the flag is shared, so `list --closed -p A-C` is typeable even though the Archive cannot honour the grammar. It must FAIL LOUDLY, exit 1: "Error: --priority-filter on --closed supports an exact letter only (got 'A-C')". Open list accepts the full grammar. No silent fallback to "no filter" - an empty result reads as "no matching issues". Once this issue is fixed (archive lines parsed for token order), the restriction can widen to the full grammar.
