Found 2026-11-13 while building codgent's issue_* harness tools (ADR 0026, in-process wrapper under a lock). Vendored todo.py (https://github.com/clach04/issue_tracker_todo.txt) mutates process-global state: apply_store() rewrites module constants TODO_FILE/DONE_FILE/ISSUES_DIR; comment reads sys.stdin.isatty() and stdout is captured by swapping sys.stdout. An in-process caller hosting multiple stores/threads must serialize under a lock and swap stdio manually - works but is a wrapper workaround for a library-level design gap. Suggested upstream directions: (1) store dir as a parameter/context object instead of module constants, (2) cmd_* write to a passed stream instead of print(), (3) comment's isatty check overridable.
