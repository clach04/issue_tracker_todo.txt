md2todo.py _write_issue_md() uses bare open(path, "w") while _read_lines() reads the source as encoding="utf-8". On Windows (cp1252) and py2 the written .issues/<hash>/issue.md can mangle or crash on non-ASCII titles/notes that were read fine. Spotted 2026-11-08 while auditing md2todo content attribution (real_test import session). Fix: io.open(path, "w", encoding="utf-8") in _write_issue_md (and audit any other bare open writes in md2todo.py: run_import / _next_index_line_number read-only, but append paths go through todo.py which is fine).
